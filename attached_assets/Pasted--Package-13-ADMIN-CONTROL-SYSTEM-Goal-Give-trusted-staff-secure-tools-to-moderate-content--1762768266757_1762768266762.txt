
🛡️ Package #13 — ADMIN CONTROL SYSTEM

Goal: Give trusted staff secure tools to moderate content, manage users/teams/shops/events/protests, review payments/payouts, view global analytics, and configure platform settings — with full audit logs and role-based access.


---

🧩 Developer Sayings / Hard Rules

> Single Admin app (separate route or subdomain), role-based access control (RBAC).

Do not touch public UI/UX; admin is isolated under /admin.

Every admin action writes an immutable audit log.

No duplicate schemas; extend canonical models only.

Sensitive ops (payouts, deletions, bans) require 2-step confirm + reason.

Respect GDPR: export/delete user data flows.

Dark-purple/cream theme; minimal, no extra colors.

🧠 Canonical Models (extend only)

type Role = 'super_admin'|'moderator'|'finance_admin'|'event_admin'|'support';
type Permission =
  | 'user:read'|'user:ban'|'user:verify'|'user:gdpr_export'|'user:gdpr_delete'
  | 'content:read'|'content:remove'|'content:restore'
  | 'team:read'|'team:verify'|'team:remove'
  | 'event:approve'|'event:remove'
  | 'protest:approve'|'protest:remove'
  | 'shop:read'|'shop:verify'|'shop:remove'|'order:refund'
  | 'payments:read'|'payouts:approve'|'refunds:approve'
  | 'settings:read'|'settings:write'
  | 'analytics:read';

type AdminAudit = {
  id: string;
  adminId: string;
  action: string; // e.g., 'user.ban', 'post.remove', 'payout.approve'
  target?: { type: string; id: string };
  reason?: string;
  before?: any;  // redacted snapshot
  after?: any;   // redacted snapshot
  createdAt: string;

🧱 Screens & Capabilities

1) Dashboard

Stat tiles: DAU/MAU, GMV/Revenue, Refund Rate, Active Protests, Open Disputes, Abuse Reports.

Queues: Reports, Pending approvals (protests/events/shops), Payout requests.

Quick links: “Today’s audit log”, “Error rate”, “Queues”.


2) Users

Search, filters (status: active/suspended/verified).

Actions: Ban/Suspend/Unsuspend, Verify, Reset 2FA, Export Data (GDPR), Delete (GDPR).

View: profile snapshot, recent posts, payments summary, reports filed.

All actions write AdminAudit.


3) Content Moderation (Feed & Media)

Tables: Posts, Comments, Stories, Media.

Tools: Remove/Restore, Shadowban, Warn user, Hash-ban media (block re-uploads).

AI assist flags (nudity/hate/spam) with risk levels (Low/Med/High).

Deep link to original content/profile.


4) Teams

Verify team, edit metadata (city/sport), remove, transfer ownership (with consent).

View sponsors, challenges history, rating adjustments (with reason).

Schedule overview; disputes attached.


5) Events

Approve public events; edit time/location on organizer request; remove illegal duplicates.

See tickets sold, refunds, attendees; contact organizer.


6) Protests

Approve/Reject; reason required on reject.

Monitor signatures, growth, reports; remove/close if policy violation.

Link to Feed post and Map pin.


7) Marketplace

Shops: verify, suspend, remove.

Products: flag/remove counterfeit content.

Orders: refund (with reason & policy window), see dispute threads.

Seller KPIs: cancellation rate, refund rate, chargeback risk (RiskBadge).


8) Payments

Wallet search; transaction explorer; export CSV for finance.

Payout approvals (Stripe Connect): amount, account, risk score, history → Approve/Reject.

Refund queue (manual review); escrow overrides (with supervisor approval).


9) Analytics (Global)

DAU/MAU charts, revenue/GMV, refunds, top sports/cities heatmap, message volume, calls.

Drill-downs open filtered lists (facts/rollups from Pkg 12).


10) Settings

Feature flags (enable/disable modules).

Abuse thresholds (rate limits, spam score).

Content policy strings (copy shown in reports).

API keys management (read-only masked).

Maintenance mode toggle.

🔒 Security & Compliance

Admin auth: separate login, short JWT lifetime, enforced 2FA.

RBAC: granular permissions; no “god mode” without super_admin.

Audit everything: action, target, before/after redacted snapshots, IP, timestamp.

Rate-limit admin APIs; IP allow-list for payout ops.

PII handling: mask emails/phones; “reveal” requires permission + reason prompt.

Backups: encrypted, tested restores; runbooks for incidents.

GDPR: export (JSON/CSV bundle) + delete user workflows (with grace period).

🧪 QA — “Done When” Checklist

✅ RBAC verified: each role sees only allowed modules/actions.
✅ Every destructive action requires confirmation + reason; appears in Audit.
✅ Reports queue flows: view → act → resolved status.
✅ Approvals (events/protests/shops) gate public visibility correctly.
✅ Refunds & payouts apply to wallets/ledgers and reflect in Payments (Pkg 11).
✅ GDPR export produces bundle; delete anonymizes user and cascades safely.
✅ Global analytics load quickly; drill-downs open the right lists.
✅ No impact on public app routes; no console errors.

🚫 Don’ts

Don’t expose admin APIs on public domain without auth/ACL.

Don’t allow silent destructive actions — audit or it didn’t happen.

Don’t keep raw PII in logs.

Don’t bypass payouts approval flow.

Don’t modify public schemas; extend and gate via admin services.
