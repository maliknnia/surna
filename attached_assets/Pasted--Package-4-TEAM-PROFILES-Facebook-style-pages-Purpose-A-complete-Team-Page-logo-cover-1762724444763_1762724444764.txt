🧠 Canonical Types (extend only; don’t fork)

type Rating = { value: number; count: number };

type Team = {
  id: string;
  name: string;
  slug: string;
  logo: string;
  cover?: string;
  city?: string;
  sport?: string;
  rating: Rating;                // aggregate of matches + reviews
  record?: { W: number; L: number; D: number };
  members: { userId: string; role: 'captain'|'player'|'coach' }[];
  sponsors?: { id: string; name: string; logo: string; link?: string; tier: 'bronze'|'silver'|'gold' }[];
  verified?: boolean;
  createdAt: string;
};

type TeamScheduleItem = {
  id: string;
  title: string;
  type: 'match'|'training'|'event';
  timeStart: string;
  timeEnd?: string;
  location: { lat: number; lng: number; address?: string };
  opponentTeamId?: string;       // for matches
  eventId?: string;              // Events package link
  status: 'upcoming'|'live'|'finished';
};

🧱 Page Layout (no redesign)

Header (TeamHeader):

Cover image (wide), overlaid circular logo, name, verified badge.

Action bar (right): Follow • Message • Join Request • Challenge • View Feed.

Stat chips: rating ⭐, W-L-D, followers, city.

Sponsor strip (mini logos) below header.


Tabs (lazy-loaded):

About: bio, city, founded date, home pitch (map “View on Map”).

Members: grid with roles; tap → person profile.

Schedule: list of TeamScheduleItem; actions: Join/Attend/Share/Navigate.

Photos: gallery; opens viewer; can post if admin.

Sponsors: tiers, description, link to brand pages.

Feed: team-only feed; fans can view, admins can post.

Donations (optional): connect to Wallet/Payments (“Sponsor the Team”, preset amounts).



---

🧩 Required Actions (all must work)

Follow / Unfollow team → updates counts everywhere.

Message → opens Messenger thread with team admins.

Join Request → queued for captain approval; shows pending state.

Challenge → opens Package #10 flow (1v1 team vs team).

View Feed → dedicated team feed route (still SURNA style).

Map → “View home pitch” centers Map on pin (Package #3).

Donate / Sponsor → Payment modal (Package #11), logs sponsorship.

Post to Team Feed (admins) → appears in global Feed for followers.



---

🔌 Backend Endpoints

GET    /api/teams/:id
POST   /api/teams/:id/follow             // toggle
POST   /api/teams/:id/message            // creates/opens thread
POST   /api/teams/:id/join-request       // user → captain queue
POST   /api/teams/:id/challenge          // delegates to challenges API
GET    /api/teams/:id/schedule
GET    /api/teams/:id/sponsors
POST   /api/teams/:id/sponsor            // wallet/payment flow
GET    /api/teams/:id/feed
POST   /api/teams/:id/feed               // admins only

Notes

Use auth & role checks (captain/admin) for privileged actions.

Emit analytics events: team_follow, team_challenge_start, team_donation.

All writes return updated counters to keep UI in sync.

🔗 Cross-Connections (wire them or it’s not “done”)

Map: “View Pitch” centers on team pin; team appears on Map layer.

Messenger: Message button → thread; Join Requests notify captain(s).

Payments: Donations/Sponsorships credit team wallet (Package #11).

Analytics: follow growth, engagement, donations visible in Package #12.

Admin: moderation tools for team content in Package #13.
