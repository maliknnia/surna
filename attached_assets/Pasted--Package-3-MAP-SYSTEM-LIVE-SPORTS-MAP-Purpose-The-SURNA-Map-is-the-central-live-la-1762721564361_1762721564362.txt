---

🗺️ Package #3 — MAP SYSTEM (LIVE SPORTS MAP)

🎯 Purpose

The SURNA Map is the central live layer of the app — it connects Players, Teams, Events, Gyms, Coaches, and Protests visually.
Users can explore, join, book, or message directly through pins.
It must be ultra-smooth, real-time, and beautifully minimalist (dark purple + cream theme).


---

🧩 Developer Sayings / Rules

> Do not duplicate maps; there is only one SURNA Map component.

All entities (places, events, teams, protests, coaches, players) use a shared schema.

Every pin must open a bottom sheet preview (not a new page).

Pin types = colors/icons only — no custom shapes.

Smooth zoom & drag > 30 fps required on mobile.

All filters and actions must sync with other modules (Feed, Messenger, Events).

  id: string;
  entity: 'player'|'team'|'event'|'coach'|'place'|'protest';
  entityId: string;
  name: string;
  lat: number;
  lng: number;

  active: boolean;

🧭 UI Flow

1️⃣ Initial Load

Ask for geolocation; fallback to manual entry.

Center map to user + radius 5 km default.

Load pins within bounds → group dense areas with clusters.

Floating buttons: 📍 Recenter  ⚙️ Filters  📶 Live Toggle.



---

2️⃣ FiltersBar

Checkboxes: Players, Teams, Events, Coaches, Places, Protests.

Dropdowns: Sport, Date Range, Distance.

Toggle: “Show only active matches” / “Show sponsored”.

Auto-refresh pins on filter change (debounce 300 ms).



---

3️⃣ Bottom Sheet

Opens on pin tap.

Content:

Thumbnail / Cover

Name + Type Icon

Short info (e.g., “Football match – Today 17:00”)

Primary Action (Join, Book, Sign, Message)

Secondary: View Full Page, Share.


Swipe up → full details modal of that entity.

Swipe down → close.



---

4️⃣ Live Mode

Toggle to receive socket updates (map_activity).

Players moving update pin positions in real time (with throttling).

Events starting glow animation for 1 minute then static.

Protests with 1000+ signatures pulse slowly.



---

5️⃣ Map Interactions

Pin tap → open bottom sheet.

Double-tap → zoom in (center pin).

Two-finger swipe → rotate disabled (default).

Long-press → “Create something here” menu (Event, Challenge, Protest).

Map idle → fetch new pins in view if moved > 1 km.

🧩 Cross-Connections

Feed → posts with location open Map at that pin.

Events → Join redirects to Map pin center.

Profiles → “View on Map” center pin of user if available.

Protests → Map pins render with signature progress.

Messenger → “Meet Location” inserts pin link in chat.



---

⚙️ Performance Rules

Use WebGL renderer for pins (Mapbox GL or Leaflet GL).

Batch pin updates (> 50 pins = cluster mode).

Throttle socket updates to 1/s per entity.

Keep memory < 100 MB in use on mobile.

No DOM repaints > 16 ms budget on pan.



---

🔒 Security & Privacy

Never store precise user location in DB without consent.

Round lat/lng to 3 decimals (~100 m) for public pins.

Private sessions (e.g., 1v1 challenge location) marked private:true.

Hide coordinates if user profile visibility = private.

🚫 Don’ts
