✊ Package #9 — PROTESTS & PETITIONS (Map + Feed + Live Signatures)

🎯 Purpose

Allow users/teams to create petitions/protests, collect signatures in real time, optionally host physical rallies, and connect everything to Map pins, Feed posts, Profiles, Events, and Messenger.


---

🧩 Developer Sayings / Hard Rules

> Do not reuse Event schema; protests are a separate entity.

Do not redesign: use SURNA tokens only (dark purple / cream; red-purple pulse for protest pins).

All actions must be functional (Sign, Share, Join Rally, Message Host).

Live signature counts must sync across Map + Feed + Protest page (socket).

Support both online-only petitions and physical protests with a location & time.

Tabs lazy-load; page shell instant.

Add moderation hooks (report/approve) for Admin (Pkg 13).

🧠 Canonical Schemas (extend only; don’t fork)

type ProtestVisibility = 'public'|'unlisted'|'private';

type Protest = {
  id: string;
  title: string;
  description: string;
  coverImage?: string;
  hostType: 'user'|'team'|'gym'|'brand';
  hostId: string;
  target?: string;                 // e.g., city council, federation
  tags?: string[];                 // sport, city, cause
  goalSignatures?: number;         // e.g., 20000
  signaturesCount: number;         // live counter (denormalized)
  visibility: ProtestVisibility;
  isPhysical: boolean;
  location?: { lat: number; lng: number; address?: string };
  startsAt?: string;               // for rallies
  endsAt?: string;
  sponsored?: boolean;             // if backed by a brand
  status: 'active'|'closed'|'removed';
  createdBy: string;               // userId
  createdAt: string;
  updatedAt: string;
  approved?: boolean;              // admin moderation flag
};

type Signature = {
  id: string;
  protestId: string;
  userId: string;
  publicName?: string;             // if user opts to display
  message?: string;                // optional note
  createdAt: string;
};

type ProtestUpdate = {
  id: string;
  protestId: string;
  title: string;
  body: string;
  media?: string[];                // images/videos
  createdAt: string;
  createdBy: string;               // host/admin
};

🧱 Screens & UX

1) Create Protest (flow)

Fields: Title, Description, Cover, Tags, Target, Visibility, Goal

Toggle: Online only or Physical rally

If physical: pick location + date/time (map picker)


Preview → Publish

On publish:

Create Map pin (if physical)

Create Feed post (auto) with live counter

Optionally send invites via Messenger



2) Protest Page (ProtestPage)

Header: title, host (clickable), cover image, SignatureBar (live), buttons: Sign, Share, Message Host, Report
Stat row: X signed / Goal + “Trending” badge if rapid growth
Tabs:

Overview — description, target, tags

Supporters — list of public signers (avatars + time)

Updates — organizer updates (cards)

Media — gallery

Rally — if physical: time, mini-map, Join Rally → adds to Calendar


Sign Drawer:

“Sign Petition” → (optional) display my name toggle, add a short message → Confirm

On success: increment counter live, add to user profile “Causes Supported”.


3) Map Integration

Protest pins shown with red-purple pulsing glow.

Tap → bottom sheet: title, short desc, counter, Sign, View Full.

Filter toggle in Map: “Show Protests”.


4) Feed Integration

On creation, auto create Protest post with live counter and Sign action.

When major milestones hit (25%, 50%, 100%), auto-post Update (host can disable).

🔌 Backend API (REST + Socket)

# Protests
POST   /api/protests                        # create (auth, rate-limited)
GET    /api/protests?near=&tag=&status=&hostId=
GET    /api/protests/:id
PATCH  /api/protests/:id                    # update (owner/admin)
POST   /api/protests/:id/close              # mark closed (owner/admin)
POST   /api/protests/:id/report             # user report
DELETE /api/protests/:id                    # admin remove (Pkg 13)

# Signatures
GET    /api/protests/:id/signatures?publicOnly=true|false&limit=&cursor=
POST   /api/protests/:id/sign               # create signature
GET    /api/protests/:id/signed             # did current user sign?

# Updates
GET    /api/protests/:id/updates
POST   /api/protests/:id/updates            # owner/admin

# Rally (physical)
POST   /api/protests/:id/joinRally          # add attendee (optional)
GET    /api/protests/:id/attendees

# Sockets
WS     /protests
  event: 'protest:created'
  event: 'protest:updated'
  event: 'protest:signed'            // {protestId, signaturesCount}
  event: 'protest:update:posted'

Rules

Increment signaturesCount atomically on sign; broadcast via socket.

If physical rally: also create/update a lightweight Event record for Calendar/Map (linked, not duplicated).

🎨 Design Specs (SURNA)

Background: near-black / dark purple.

Text: cream; meta grey.

Progress bar: purple → red gradient (subtle), animated on growth.

Protest map pin: red-purple pulse (SVG + CSS animation).

Buttons: cream bg + purple text; Sign is primary.

No extra colors; no heavy gradients. Minimal, respectful, legible.



---

🔒 Security, Privacy & Moderation

Creation rate-limit (e.g., 3/hour per user).

Content moderation on title/description (profanity/abuse filters).

Approval flow: if approved=false, hide from discovery (only direct link visible).

Signature privacy: default private; user must opt-in to display name.

Anti-spam: 1 signature per user per protest; bot detection (IP/device checks).

Reporting: any user can report; admin tools to remove/close with audit log.

Location safety: for rallies, show approximate location radius until user joins.



---

⚙️ Performance

Debounce feed/map updates; use socket for counter increments.

Paginate supporters list (cursor-based).

CDN for cover/media.

Keep ProtestPage hydration < 600 ms; tabs lazy-load.
